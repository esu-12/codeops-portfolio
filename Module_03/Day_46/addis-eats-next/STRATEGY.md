# Addis Eats Rendering Strategy

## Purpose

This document records the rendering strategy of the Addis Eats Next.js App Router application. Strategies are based on the successful production build output and checked against the implementation.

## Route Strategy Table

| Route | Build indicator | Strategy | Reason |
|---|---|---|---|
| `/` | `○` | Static | Home page is prerendered. |
| `/_not-found` | `○` | Static | Next.js not-found page is prerendered. |
| `/api/dishes` | `ƒ` | Dynamic API | Handles requests for the dish collection. |
| `/api/dishes/[id]` | `ƒ` | Dynamic API | Looks up a dish by ID. |
| `/api/dishes/search` | `ƒ` | Dynamic API | Handles dish search and pagination. |
| `/api/menu` | `ƒ` | Dynamic API | Provides the menu API response. |
| `/api/orders` | `ƒ` | Dynamic API | Handles order submissions and authentication. |
| `/api/orders/[id]` | `ƒ` | Dynamic API | Retrieves an order by ID with an authentication check. |
| `/api/time` | `ƒ` | Dynamic API | Returns a time API response. |
| `/cart` | `○` | Static | Client-side cart interface. |
| `/checkout` | `○` | Static | Client-side checkout interface; access is also protected by the route middleware/proxy. |
| `/login` | `○` | Static | Client-side login form. |
| `/menu` | `ƒ` | Dynamic server rendering | Fetches menu data on the server; revalidation is configured for 60 seconds. |
| `/menu/[id]` | `ƒ` | Dynamic server rendering | Resolves and renders an individual dish on the server. |
| `/menu/[id]/opengraph-image-vh8hot` | `ƒ` | Dynamic image generation | Generates an Open Graph image for an individual dish. The suffix is generated by Next.js. |
| `/opengraph-image` | `○` | Static image generation | Provides the site's Open Graph image. |
| `/orders` | `ƒ` | Dynamic server rendering | Reads the current session and renders the order history. |
| `/orders/[id]` | `ƒ` | Dynamic server rendering | Resolves order status using the current session. |
| `/register` | `○` | Static | Client-side registration form. |
| `/robots.txt` | `○` | Static metadata route | Provides crawler rules. |
| `/sitemap.xml` | `○` | Static metadata route | Provides the sitemap; the build reports a one-hour revalidation interval and a one-year expiration. |

## Build Verification

The production build completed successfully with `npm run build`.

Next.js reported:

- `○` — Static, prerendered as static content.
- `ƒ` — Dynamic, server-rendered on demand.

The route table reflects the latest recorded production build. Run a new production build after subsequent changes and update this table if the output changes.

## Endpoint Verification

The following production-server checks have been observed:

| Endpoint or request | Result |
|---|---|
| `GET /api/dishes` | `200 OK` |
| `GET /api/menu` | `200 OK` |
| `GET /api/time` | `200 OK` |
| `GET /api/dishes/search` | `200 OK` |
| `GET /api/dishes/not-a-real-id` | `404 Not Found` |
| `GET /api/orders/test-order` without authentication | `401 Unauthorized` |
| `POST /api/orders` with `{}` without authentication | `401 Unauthorized` |
| `GET /checkout` without authentication | `307 Temporary Redirect` to login |
| `GET /orders` without authentication | `307 Temporary Redirect` to login |

The unauthenticated order-submission test does not verify the `422` validation response because authentication is checked first. Validation must also be tested using an authenticated request.

## Failure Testing

The menu has been observed to display its dish content when JavaScript is disabled after temporarily renaming the root `app/loading.jsx` file to `app/loading.jsx.disabled`.

This is a diagnostic change, not yet a complete acceptance test of every route. Re-run the production build and repeat the JavaScript-disabled check before final submission.
